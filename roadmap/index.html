ROADMAP

Five hops to 1.0. The first one has landed.

Each phase ends with a tagged pre-release. The hosted service opens at 1.0, after phase 5.

startv0.1v0.2v0.3v0.4v0.5 / 1.0
  1. Shipped: v0.1.0

    Phase 1
    Foundation

    • Firecracker microVM per machine
    • Create, start, stop, reboot, delete
    • SSH, hopbox connect, web terminal
    • Exec and file copy
    • An HTTPS URL per machine
    • Sign-in with GitHub, Google, or email
    • Orgs, roles, API keys, sealed secrets
    • API, TypeScript SDK, CLI, console
    • MCP server for AI agents
    • Default image with Docker and dev tools
  2. Next: v0.2

    Phase 2
    Fleet

    • Machines spread over many servers
    • A private mesh between servers
    • Separate edge servers
    • Machines moved off a server on drain
    • More machine sizes
    • An admin area in the console
  3. v0.3

    Phase 3
    Memory tiers

    • Standby and hibernate
    • Checkpoints and versioned snapshots
    • Forks of a running machine
    • Backups to object storage
    • Wake on connect
    • Extra disks
  4. v0.4

    Phase 4
    Networking

    • Org private networks and internal DNS
    • Tag networks
    • Egress allowlists
    • Placeholder secrets
    • Subdomain routes and custom domains
    • Org wildcard domains
    • Raw TCP and UDP ports
    • Isolated machines
  5. v0.5

    Phase 5
    Agent experience

    • Coding agents preinstalled
    • Agent logins injected at boot
    • A CLI inside every machine
    • A desktop and an agent browser
    • Run deploys and cron runs
    • Integrations and automations
    • A GitHub Action for pull requests
    • OIDC single sign-on
    • A Python SDK
  6. 1.0

    Hosted service opens

    Version 1.0 closes phase 5 and opens the hosted service. Until then, hopbox is in preview, and machines and their data can be erased.
