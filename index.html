Two layers, one project

A compute core, and a dev-env built on it.

Hopbox is open source and self-hosted, top to bottom. boxd is the compute layer — boxes over SSH. hopbox is a development-environment control plane that runs on top of it. Use either on its own.

● boxd — compute layer

Compute boxes over SSH

A Firecracker microVM the moment you connect.

Point SSH at a boxd host and a microVM boots on connect: a real Linux kernel, hardware-isolated, sub-second cold start. Your SSH key is the only credential.

  • Durable disk — survives suspend/resume, restart and host reboot.
  • Auto-suspend to disk when idle, instant wake from a snapshot.
  • Image catalog — name:ubuntu-22.04@host, tooled with git, vim and friends.
  • Ephemeral by default, with a persistent tier for registered keys.
  • box-guest — an in-box CLI and MCP server, so an agent can manage its own sandbox.
  • Isolated by default — network isolation plus an egress firewall.
ssh myproject@box.hopbox.dev
◆ hopbox — dev-env platform

A dev-environment control plane

Workspaces, ingress and identity on top of boxd.

hopbox turns boxes into managed development environments: persistent workspaces, public URLs, accounts and a real API — vendor-neutral and self-hosted on your infrastructure.

  • Storage-homes — files persist across box rebuilds.
  • HTTPS ingress — a gateway gives every workspace its own URL.
  • Accounts & identity — OIDC or static tokens.
  • gRPC API + hopbox CLI to drive it all.
  • SSH into workspaces with CA-signed certs — VS Code Remote-SSH, scp, sftp.
  • Pluggable compute — docker, kubernetes or microVM. No lock-in.
hopbox up && code --remote ssh-remote+myws ~
boxd is the compute layer · hopbox is a dev-env that uses it
Why boxes over SSH

Real isolation. Zero ceremony.

SSH is the entire interface. The username carries the spec, your key carries the identity — and a hardware-isolated VM does the rest.

❯

One command, a whole VM

ssh name@host and you're root in a fresh microVM. No signup, no cloud console, no provisioning step.

⚡

Sub-second boot

Firecracker cold-starts in a fraction of a second, and idle boxes wake from a disk snapshot just as fast.

🔒

Hardware isolation

Each box is its own KVM guest with a real kernel — not a shared-kernel container. Network-isolated with an egress firewall by default.

💾

Durable, not disposable

Disk survives suspend, restart and host reboots. Ephemeral by default, persistent for registered keys.

📦

Image catalog

ssh images@host lists them; ssh name:debian-12@host picks one — pre-tooled with git, vim and the basics.

🤖

Agent-ready

box-guest ships an in-box CLI and MCP server, so an AI agent inside a box can manage its own sandbox.
