Hopbox is a self-hosted, vendor-neutral control plane for development environments. Run one control plane; give your team isolated, persistent, reproducible workspaces on Docker or Kubernetes — reachable from anywhere, even behind NAT or a private cluster.

Get started How it works

Reverse-dialing agent

Each workspace dials out and holds one multiplexed connection. The control plane never needs a route in — NAT and private clusters just work.

Swappable providers

Compute, storage, ingress, identity, build, metering — six versioned contracts. Docker today, Kubernetes the same day, your brick tomorrow.

Unlimited endpoints

A Host-routed HTTPS gateway with one wildcard cert gives every workspace its own URL — no port allocation, no per-user DNS.

Declarative core

A reconciler drives each workspace toward its spec and heals it when it drifts. The same engine scales from a laptop to a platform team.

# spin up a workspace, run a command, open a shell
hopbox create demo --image ubuntu:24.04
hopbox exec demo -- uname -a
hopbox shell demo

# expose a port — reachable at https://app-<id>.gw.your-domain
hopbox create web --image python:3-slim --expose app:8000

Self-hosted and open. Built as the successor to the original hopbox SSH gateway — the good parts of the UX, with the seams as the architecture.
