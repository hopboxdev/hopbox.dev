USE CASES

One machine per developer, per preview, per agent, per customer.

Works today

Development environments

A Linux machine that keeps its disk between sessions. Open it from any laptop with SSH, or from a browser tab.

hopbox new box1
ssh box1.hop
Works today

Preview environments

Run a branch in its own machine and share one URL. Snapshots of the main branch make it faster in v0.3.

hopbox url port box1 3000
hopbox url public box1
Works today

Coding agents

Your agent drives machines through MCP. In v0.5, machines come with coding agents preinstalled and signed in.

claude mcp add --transport http \
  hopbox https://dev.hopbox.dev/mcp
Works today

Always-on assistants

Give a machine a start command and a restart policy. It comes back after every reboot.

hopbox machine update box1 \
  --start-command 'python3 bot.py'
Works today

One machine per customer

Build agentic SaaS on the API: each end customer gets an isolated machine. Private networks between them come in v0.4.

hopbox new box1 --json
Works today

Agent swarms

Start many machines from a script or the SDK and run a task in each. Forks of a running machine come in v0.3.

for i in 1 2 3; do hopbox new box$i; done
v0.3

Reinforcement learning environments

Save a machine as a snapshot, fork it many times, and reset each run to the same state.

v0.4

Untrusted code

Every machine is a microVM today. Isolated machines with no personal credentials and an egress allowlist come in v0.4.

Later release

Machines for agent platforms

Run the tools of outside agent platforms, such as Claude Managed Agents and the OpenAI Agents API, in hopbox machines.

v0.3, then a GitHub Action

Review a pull request by booting it.

Every pull request gets a full Linux machine with the build in it, a public URL, and an SSH command. No virtual machine in the browser, and no build cache to set up.

  1. 01A pull request opens. CI calls the hopbox API.
  2. 02hopbox starts a machine from a snapshot of the main branch, in seconds.
  3. 03The job fetches the pull request into the machine and builds it.
  4. 04The app URL goes public. A web terminal can come with it.
  5. 05A comment on the pull request holds the URLs and the SSH command.
  6. 06The pull request closes. The machine is deleted.
